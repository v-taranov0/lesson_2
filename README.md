# Домашнее задание к уроку №2. HTTP, REST и работа с внешними сервисами

Соберите CLI-утилиту «Сводка по городу»: она получает погоду и курс выбранной валюты из внешних API, приводит ответы к единому виду, применяет простые правила и печатает результат в stdout.

## Пример домена — «Сводка по городу»

- программа получает из внешних API погоду и курс валюты к рублю (по умолчанию доллар);
- после получения данных применяет простые правила: если температура `< 0`, добавляет флаг `warm_clothes: true`; если курс `> 100`, добавляет `expensive: true`;
- запуск `python main.py --city Moscow` печатает сводку в консоль (курс USD→RUB), `python main.py --city Moscow --currency EUR` — курс евро.

## Внешние API

Можно заменить аналогами с документацией.

- **Погода:** [Open-Meteo](https://open-meteo.com/) — без ключа; сначала геокодинг города, затем прогноз по координатам. Альтернатива — [OpenWeatherMap](https://openweathermap.org/api).
- **Курсы:** [Frankfurter](https://frankfurter.dev/) — `GET https://api.frankfurter.dev/v2/rate/{currency}/RUB` (по умолчанию `{currency}` = `USD`).

> На слайдах урока: timeout — слайд 16, retry — слайды 17–21, клиент и валидация — слайды 25–29.

## Структура проекта

```text
city_summary/

├── requirements.txt
├── README.md

│   ├── weather.py                 # get_weather(city) -> dict
│   └── rates.py                   # get_rate(currency) -> float
├── processing/                    # сборка сводки и правила предобработки
│   ├── __init__.py
│   ├── preprocessing.py           # warm_clothes, expensive, ...
│   └── service.py                 # build_city_summary(city, currency="USD") -> dict
└── tests/                         # опционально
    └── test_preprocessing.py
```

Модуль `clients/http.py` можно объединить с клиентами, если так получается проще.

### Разделение ответственности

- **`clients/`** — HTTP-запросы, timeout, retry, разбор ответов и перевод ошибок внешних сервисов в исключения приложения. Здесь нет вывода в консоль и разбора CLI-аргументов.
- **`processing/`** — правила предобработки и сборка сводки из ответов клиентов.
- **`main.py`** — точка входа CLI: аргументы, вызов `build_city_summary`, печать результата и коды выхода.

## Требования

### Запуск

```bash
python main.py --city Moscow                    # валюта по умолчанию — USD
python main.py --city Moscow --currency EUR     # другая валюта
```

### Пример текстового вывода

```text
Город: Moscow
Погода: -3.2°C, clear sky
Тёплая одежда: да
USD→RUB: 92.15
Дорогой курс: нет
```

### Пример структуры данных

Словарь, который собирает `build_city_summary`:

```json
{
  "city": "Moscow",
  "weather": {
    "temp_c": -3.2,
    "description": "clear sky",
    "warm_clothes": true
  },
  "rates": {
    "currency": "USD",
    "rate_to_rub": 92.15,
    "expensive": false
  }
}
```

### Предобработка данных

Минимум два правила на ваш выбор, примеры выше — ориентир.

- логика должна зависеть от **полученных данных**: порога температуры, порога курса, пустого описания погоды, значения по умолчанию и т.д.;
- правила — в `processing/preprocessing.py`, не в клиентах внешних API.

### Технические требования

- внешние вызовы — только `GET`;
- timeout ≤ 10 с на каждый внешний запрос;
- не менее двух повторов после первой попытки при `requests.exceptions.Timeout`, `requests.exceptions.ConnectionError` и временных 5xx (500/502/503/504); для 429 учитывать числовой `Retry-After`;
- аргумент `--currency` — ISO-код валюты, по умолчанию `USD`; если код валюты не найден, код выхода `3`;
- коды выхода: `0` — успех, `2` — ошибка аргументов, `3` — город или код валюты не найден, `4` — внешний сервис недоступен после retry;
- если используете OpenWeatherMap, ключ берите из переменной окружения `WEATHER_API_KEY` и не храните его в репозитории; для Open-Meteo ключ не нужен.

### Дополнительно

`logging` с `run_id`, кэш курса на 5 минут, тесты клиентов через `unittest.mock`, типизация или флаг `--json`.
